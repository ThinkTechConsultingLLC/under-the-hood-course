# M7 — Version control: Git & GitHub

> Somewhere on your computer is a file called something like `final_v2_FINAL_actually-final`. Today
> you learn the tool that ends that forever — a time machine for your work — and the cloud home where
> the entire software world keeps its code. By the end you'll have your own project on GitHub.

**Today's win:** you create a Git repo, save labelled snapshots (commits), view its history, branch to try something safely, and push your project up to **GitHub**.

### Today you will
- Track your work with **commits** and read the **history** (`git init`, `add`, `commit`, `log`)
- **Branch** to experiment safely, then **merge** it back
- Understand **Git vs GitHub** (local vs cloud) and **push** a repo to your GitHub

### Environment
We work in a **Codespace** — Git is pre-installed and already signed in to your GitHub. New to it? See **[How to open your Codespace](../resources/install-guides/codespaces.md)**.

### If you get stuck
- Git is full of undo — almost nothing you do is permanent. Commit early, commit often.
- Re-read the **✅ You should now see** line; compare with your breakout partner.
- Keep the [cheat-card](../resources/cheat-cards/linux-commands.md) handy and use `git status` whenever you're unsure where you are.

### Optional challenge
Pair up: one of you pushes a repo to GitHub and adds the other as a collaborator. The second person
**clones** it, makes a commit, and pushes back. You just collaborated the way real teams do.
